Computer Architecture Study Guide

Chapter 10: Cache Memory

  • 1. Cache and Cache Operation
    • What is a Cache? A small, incredibly fast memory layer situated between the CPU and the slower Main Memory (RAM).
    • Purpose: To store frequently used data and eliminate CPU wait times.
    • How it Operates: It follows a simple check-and-fetch process:
      • Cache Hit: The CPU checks the cache, finds the data, and retrieves it instantly.
      • Cache Miss: The CPU checks the cache, does not find the data, and must fetch it from Main Memory (copying it into the cache for future use).
Diagram: Cache Operation Flow
CPU requests data | v [ Check Cache ] / \ YES NO / \ HIT MISS | | v v Delivered Fetch from RAM Instantly -> Copy to Cache -> Deliver to CPU
  • 2. Cache Memory Principles
    • The Core Rule: The entire system relies on the Principle of Locality, which assumes data access is not random.
    • Temporal Locality (Time): If a CPU accesses a piece of data, it is highly likely to access that exact same data again in the near future.
    • Spatial Locality (Space): If a CPU accesses a piece of data, it is highly likely to access data located right next to it in memory.
    • Result: Because of these principles, a tiny cache can successfully predict and hold the necessary data, acting as an invisible speed booster.
Diagram: Principle of Locality
Memory Array: [ Block A ] [ Block B ] [ Block C ] [ Block D ] Temporal: CPU uses "Block B" now ---> CPU will likely use "Block B" again soon. Spatial: CPU uses "Block B" now ---> CPU will likely use "Block A" or "Block C" next.
  • 3. Elements of Cache Design
    • The Goal: Maximize the "hit rate" while minimizing cost and access time.
    • The Challenge: Engineers must carefully balance trade-offs rather than just adding more memory.
    • Core Design Elements:
      • Cache Size: How much physical space it takes up.
      • Line Size: How data is grouped together.
      • Write Policies: The rules for what happens when the CPU modifies (writes to) data.
      • Mapping Function: The system used to locate data inside the cache.
  • 4. Cache Size
    • The Benefit of Large Caches: Can hold more data, which generally increases the hit rate.
    • The Drawback of Large Caches: Physically larger, exponentially more expensive to manufacture, and slower to search through.
    • The Goal: Find the "sweet spot"—large enough to be useful, but small enough to remain fast and affordable.
Diagram: Cache Size Trade-off
(Fast & Cheap) ^ | Small Cache | v <----- SIZE -----> ^ | Large Cache | v (Slow & Expensive)
  • 5. Mapping Function
    • The Problem: Main memory is huge, and cache is tiny. We need strict rules to dictate where a block of main memory goes inside the cache, and how to find it later.
    • Direct Mapping: Every memory block is mathematically forced to map to exactly one specific line. Pro: Fast. Con: High risk of "thrashing".
    • Associative Mapping: A memory block can be placed into any available line. Pro: Solves thrashing. Con: Searching is slow and expensive.
    • Set-Associative Mapping: Divides the cache into "sets". A block maps to a specific set, but can go into any line within that set. Pro: Reduces thrashing while keeping search times fast.
Diagram: Mapping Functions Comparison
MAIN MEMORY BLOCKS: [ M0 ] [ M1 ] [ M4 ] [ M5 ] 1. DIRECT MAPPING (Forced to 1 specific line) Cache: [ Line 0 ] <--- M0 AND M4 fight for this spot (Thrashing!) [ Line 1 ] <--- M1 2. ASSOCIATIVE MAPPING (Can go anywhere) Cache: [ Line 0 ] <--- M0 [ Line 1 ] <--- M4 (Searches ALL lines to find them) [ Line 2 ] <--- M1 3. SET-ASSOCIATIVE MAPPING (Forced to 1 Set, flexible within it) Cache: [ Set 0: Line 0 ] <--- M0 goes here [ Set 0: Line 1 ] <--- M4 goes here (No thrashing, limited search!) [ Set 1: Line 2 ] <--- M1 goes here [ Set 1: Line 3 ]

Chapter 11: Pipelining

  • 1. Pipelining
    • What is it? A technique where multiple instruction executions are overlapped to improve CPU throughput.
    • The Goal: Instead of finishing one instruction completely before starting the next, the CPU completes one instruction every clock cycle.
Diagram: Basic 3-Stage Pipeline Flow
Time ---> Cycle 1 Cycle 2 Cycle 3 Cycle 4 ------------------------------------------------ Instr 1: [ Fetch ] [ Decode ] [ Execute ] [ Done ] Instr 2: [ Fetch ] [ Decode ] [ Execute ] Instr 3: [ Fetch ] [ Decode ]
  • 2. Issues and Hurdles
    • The Core Problem: The next instruction often depends on the previous one, causing "Hazards" that stall the pipeline.
    • Structural Hazard: Hardware cannot support overlapping instructions (e.g., trying to fetch and access memory at the same time).
    • Data Hazard: An instruction needs data that a previous instruction hasn't finished calculating yet.
    • Control Hazard: The CPU doesn't know which instruction to fetch next because it is waiting for a branch/jump decision.
Diagram: Pipeline Stall (Bubble) due to a Hazard
Cycle 1 Cycle 2 Cycle 3 Cycle 4 Cycle 5 ---------------------------------------------------- Instr 1: [ Fetch ] [ Decode ] [ Execute ] [ Done ] [ ] Instr 2: [ Fetch ] [ STALL ] [ STALL ] [ Decode ] Instr 3: [ STALL ] [ STALL ] [ Fetch ] ^--- "Bubble" caused by waiting for data
  • 3. Exception Handling
    • What is an Exception? Unpredictable, disruptive events like dividing by zero or accessing invalid memory.
    • The Solution: Precise Exception Handling. The CPU stops the pipeline, flushes out (erases) all instructions that followed the exception, saves the exact state of the CPU, and jumps to an exception-handling routine.
Diagram: Pipeline Flushing on Exception
Cycle 1 Cycle 2 Cycle 3 Cycle 4 Cycle 5 ---------------------------------------------------- Instr 1: [ Fetch ] [ Decode ] [EXCEPTION] [ FLUSH ] [ Handle ] Instr 2: [ Fetch ] [ FLUSH ] [ FLUSH ] [ ] Instr 3: [ FLUSH ] [ FLUSH ] [ ] ^--- Erasing ghost instructions
  • 4. Parallelism
    • The Concept: Doing multiple things at the exact same time (Instruction-Level Parallelism).
    • Superscalar Execution: The CPU has multiple identical pipelines side-by-side. It dispatches independent instructions to different pipelines simultaneously.
Diagram: Moving to Parallelism (Superscalar)
Single Pipeline: Instr 1: [ Fetch ] [ Decode ] [ Execute ] Instr 2: [ Fetch ] [ Decode ] [ Execute ] Superscalar (2 Pipelines): Cycle 1 Cycle 2 Cycle 3 -------------------------------- Pipeline 1: [ Fetch1 ] [ Decode1 ] [ Execute1 ] Pipeline 2: [ Fetch2 ] [ Decode2 ] [ Execute2 ] ^--- Both instructions are executed at the exact same time!

Instruction Set Design: RISC and CISC Architectures

  • 1. Overview
    • Instruction Set Architecture (ISA): The vocabulary of the CPU (e.g., ADD, SUBTRACT, LOAD).
    • CISC (Complex Instruction Set Computer): Aims to execute complex, multi-step tasks using a single, highly specialized instruction.
    • RISC (Reduced Instruction Set Computer): Aims to use only simple, basic instructions, requiring multiple steps to complete a complex task.
Diagram: The ISA Translation Layer
High-Level Code (e.g., C++) | v [ COMPILER / SOFTWARE ] | v Instruction Set (RISC or CISC) ---> Uses "Addressing Modes" to locate data | v [ CPU HARDWARE ]
  • 2. History
    • The CISC Era (1970s): Memory was expensive and slow. Engineers put complexity into the hardware to make compiled software smaller.
    • The RISC Revolution (1980s): Memory became cheaper. Researchers shifted complexity from hardware back to software (compilers), creating RISC to execute simple instructions in a single clock cycle.
Diagram: Shift in Complexity
1970s (CISC): Software = Simple ----> Hardware = Complex & Slow (Memory was expensive, so code had to be tiny) 1980s+ (RISC): Software = Complex ----> Hardware = Simple & Fast (Compilers do the heavy lifting; hardware just races through simple steps)
  • 3. Comparison
    • Instruction Design: RISC uses fixed-length instructions (easy to decode). CISC uses variable-length instructions (harder to decode).
    • Execution Time: RISC instructions take 1 clock cycle. CISC instructions take multiple clock cycles.
    • Registers: RISC relies on a massive array of CPU registers. CISC relies on fewer registers and interacts directly with RAM.
Diagram: Side-by-Side Execution Comparison
Task: Multiply a number in memory by 2 and save it back. CISC Approach (One complex instruction): [ MULT_MEM_ADDR ] ---> CPU does the loading, multiplying, and storing internally. RISC Approach (Multiple simple instructions): [ LOAD ] (Get data from memory to register) ---> Cycle 1 [ SHIFT ] (Multiply by 2 inside register) ---> Cycle 1 [ STORE ] (Put data back to memory) ---> Cycle 1 (Takes 3 instructions, but each is blazingly fast)
  • 4. Advantages and Disadvantages
    • RISC Advantages: Extremely high clock speeds; simpler, cheaper hardware; highly optimized by modern compilers.
    • RISC Disadvantages: Code size is much larger; performance heavily depends on the quality of the compiler.
    • CISC Advantages: Much smaller program sizes; easier for humans to write assembly code; strong legacy support.
    • CISC Disadvantages: Hardware is complex, power-hungry, and runs hotter; variable instruction lengths create pipeline bottlenecks.
Diagram: The Trade-off Scale
RISC Side CISC Side (Simpler) (Complex) | | Faster Clock Speeds Smaller Code Size Lower Power Consumption Easier Assembly Writing Better for Pipelining Strong Backward Compatibility | | [ Larger Files ] [ Slower Hardware ]
